PASO 5 - CONFIGURACIÓN DE ESLINT
----------------------------------------------------------------
Debido a que se instaló ESLint v10, el formato de configuración
cambió. ESLint v9+ ya no acepta .eslintrc.json, requiere el
nuevo formato eslint.config.js (o .mjs).

PROBLEMA ENCONTRADO:
- ESLint v10 no reconoce el archivo .eslintrc.json
- Error: "ESLint couldn't find an eslint.config.(js|mjs|cjs) file"

SOLUCIÓN:
Se creó el archivo eslint.config.mjs (formato ESM) con la
siguiente configuración adaptada al proyecto:

  import js from '@eslint/js';

  export default [
    js.configs.recommended,
    {
      rules: {
        'no-console': ['warn', { allow: ['warn', 'error'] }],
        'no-unused-vars': ['warn', { argsIgnorePattern: '^_' }],
      },
      languageOptions: {
        ecmaVersion: 'latest',
        sourceType: 'module',
        globals: {
          describe: 'readonly',
          it: 'readonly',
          expect: 'readonly',
          beforeEach: 'readonly',
          afterEach: 'readonly',
          beforeAll: 'readonly',
          afterAll: 'readonly',
        },
      },
    },
    {
      files: ['jest.config.js', '*.config.js'],
      languageOptions: {
        sourceType: 'commonjs',
        globals: {
          require: 'readonly',
          module: 'writable',
          __dirname: 'readonly',
          __filename: 'readonly',
        },
      },
    },
    {
      ignores: ['node_modules/', 'dist/', 'build/', 'coverage/'],
    },
  ];

Nota: Se usó extensión .mjs porque el package.json no tiene
"type": "module", evitando así el error:
"Cannot use import statement outside a module"

PASO 6 - CONFIGURACIÓN DE JEST
----------------------------------------------------------------
PROBLEMA ENCONTRADO:
- Al hacer commit, Husky intentaba correr "npm test" pero
  Jest no estaba instalado.
- Error: "'jest' is not recognized as an internal or external command"

SOLUCIÓN:
Se instaló Jest y se inicializó su configuración:

  npm install --save-dev jest ts-jest @types/jest
  npx ts-jest config:init

Se agregó el flag --passWithNoTests en package.json para
evitar que Jest falle cuando aún no hay tests reales:

  "test": "jest --passWithNoTests"

Se creó un test placeholder en .husky/src/__tests__/app.test.js:

  describe('Setup', () => {
    it('should pass initial test', () => {
      expect(true).toBe(true);
    });
  });

PASO 7 - CONFIGURACIÓN DE HUSKY
----------------------------------------------------------------
Se instaló y configuró Husky para los hooks de git:

  npx husky-init && npm install

Se editó .husky/pre-commit, última línea:
  npx lint-staged --config .lintstagedrc.json

Se agregó hook pre-push para bloquear si los tests fallan:
  npx husky add .husky/pre-push "npm test"

----------------------------------------------------------------
PASO 8 - CONFIGURACIÓN DE LINT-STAGED
----------------------------------------------------------------
PROBLEMA ENCONTRADO:
- lint-staged escaneaba dentro de node_modules y encontraba
  el package.json de la librería bs-logger con formato
  obsoleto de configuración (clave "linters" y "git add").
- Error: "Invalid value for 'linters'"

SOLUCIÓN:
Se creó el archivo .lintstagedrc.json en la raíz del proyecto
para forzar a lint-staged a usar solo esta configuración:

  {
    "*.{js,ts}": ["eslint --fix", "prettier --write"],
    "*.{json,md,html,css}": ["prettier --write"]
  }

Se modificó .husky/pre-commit para apuntar explícitamente
al archivo de configuración:

  npx lint-staged --config .lintstagedrc.json

Se eliminó la sección "lint-staged" del package.json para
evitar conflicto entre dos fuentes de configuración.

----------------------------------------------------------------
PASO 9 - CONFIGURACIÓN DE .GITIGNORE
----------------------------------------------------------------
PROBLEMA ENCONTRADO:
- node_modules no estaba siendo ignorado por git, lo que
  causaba que lint-staged escaneara esa carpeta.

SOLUCIÓN:
Se creó el archivo .gitignore en la raíz con el siguiente
contenido principal:

  node_modules/
  .env
  dist/
  build/
  *.log
  coverage/
  .DS_Store
  Thumbs.db

Se ejecutó el siguiente comando para dejar de trackear
node_modules que ya estaba siendo seguido por git:

  git rm -r --cached node_modules

----------------------------------------------------------------
PASO 10 - CONFIGURACIÓN DE GITHUB ACTIONS (CI)
----------------------------------------------------------------
Se creó el directorio y archivo de workflow:

  mkdir -p .github/workflows
  touch .github/workflows/ci.yml

El pipeline CI se ejecuta automáticamente en:
- Push a las ramas main y develop
- Pull Request hacia main y develop

Pasos del pipeline configurados:
  1. Code Checkout
  2. Setup Node.js (matrix: 18.x y 20.x)
  3. Clean dependency install (npm ci)
  4. Security auditing (npm audit)
  5. Format check (Prettier)
  6. Lint check (ESLint)
  7. Type check (TypeScript)
  8. Run Tests (Jest)
  9. Build Check
